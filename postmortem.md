# Короткий разбор: как это делалось

## Порядок работы

Сначала решил, что считается готовым: сообщение боту доходит до лида с тегом в CRM по
внешней ссылке. Всё, что не ведёт к этому, в MVP не попало.

Дальше по шагам:

1. **Инфраструктура до кода.** Завёл бота у @BotFather, положил токен в `.env`, поставил
   `cloudflared`. Сразу стало видно ограничение: для `api_id`/`api_hash` нужен
   my.telegram.org, а он несколько раз молча не создал приложение — форма сбрасывалась в
   пустую, в том числе со второго аккаунта.
2. **Решение по стеку из-за этого ограничения.** Telethon для бота требует
   `api_id`/`api_hash`, поэтому бота увёл на Bot API (long polling на `httpx`) — ему
   хватает токена. Telethon оставил там, где он действительно нужен и не заменяется, —
   на подключении обычного аккаунта (пункт 2). Это развязало обязательные пункты от
   ключей, которые я не контролирую.
3. **Код.** FastAPI + SQLAlchemy 2 (async) + SQLite, Jinja2 для страниц. Бот и юзербот —
   фоновые задачи в `lifespan` того же процесса, с перезапуском при падении. Общий слой
   операций над лидами один на все три источника, чтобы «лид из бота» и «лид руками» не
   разъехались в две разные сущности.
4. **Тесты.** После полировки — 46 тестов на pytest + httpx: ручное создание и откат
   при ошибке тега, авторизация и страницы ошибок, теги и фильтр, поля и статусы,
   поиск и пагинация, диалог и ответы Bot API без сети, smoke с очисткой своих данных,
   юзербот без ключей, повтор сохранения после сбоя, валидация форм и сквозной
   сценарий от диалога бота до фильтра по тегу без сети, обработчик входящих юзербота
   с подменённым клиентом.
5. **Проверка руками.** Написал боту с телефона реальный диалог, лид №1 появился в CRM;
   повесил тег «Срочно», добавил второго лида руками с тегом «сайт», проверил, что
   фильтр по каждому тегу показывает только своего. Всё — через внешнюю ссылку
   `cloudflared`, не по localhost.

Что сломалось по дороге: SQLAlchemy async не поднялся без `greenlet` (в зависимостях
его не было — добавил); первая версия писала в лог полный URL запроса к Telegram, а в
нём лежит токен бота — приглушил логгер `httpx`; время показывалось в UTC, добавил
перевод в часовой пояс сервера.

## Какие ИИ-инструменты использовал и для чего

Основной инструмент — **Claude (Claude Code)**, в режиме, где он сам работает с файлами
и терминалом на моей машине. Конкретно по задачам:

- **Разбор ТЗ и границы MVP.** Прогнал требования и попросил выделить, что обязательно, а
  что «если успеете», чтобы не распыляться.
- **Генерация каркаса** — модели, слой операций, роуты, шаблоны. Правил руками там, где
  модель предлагала лишние абстракции.
- **Разбор ошибок.** Трейс с `greenlet`, возня с кодировками в PowerShell, поведение
  `pytest-asyncio` — быстрее, чем гуглить.
- **Рутина на машине.** Создание бота в @BotFather, установка `cloudflared`, прогон
  тестов, поднятие туннеля, сквозная проверка по внешней ссылке.
- **Тексты** — этот разбор и набросок продукта: черновик от модели, формулировки и
  акценты мои.
- **Полировка в Codex** — типизация Bot API, атомарное создание, страницы ошибок,
  поиск и пагинация, сохранение черновика при сбое, расширение проверок pytest.

Чего **не** отдавал модели: выбор Bot API вместо Telethon для бота, решение «один
собеседник = один лид», что оставить за скобками MVP и где проходит граница готового.
Это решения, за которые потом отвечать.

## Что сделал бы, будь ещё неделя

1. **Закрыть пункт 2 по-настоящему** — получить ключи, войти аккаунтом, прогнать личку
   на реальной переписке. Сейчас это код, который не проверен на живом трафике.
2. **Ответ менеджера из карточки лида.** Сейчас CRM только читает — это половина
   ценности. Отвечать из одного окна важнее, чем любая аналитика.
3. **Отдельная таблица сообщений** вместо склейки переписки в одно текстовое поле, и
   история изменений по лиду.
4. **Postgres и нормальный деплой** вместо SQLite и временного туннеля: systemd-юнит,
   свой домен, бэкапы. Миграция дешёвая — слой доступа уже асинхронный.
5. **Живучесть бота:** черновики диалога в базу вместо памяти процесса и переход с
   long polling на вебхук, когда появится постоянный домен.
6. **Дедупликация** — один человек, написавший и боту, и в личку, сейчас станет двумя
   лидами. Склейка по контакту или `tg_chat_id`.
